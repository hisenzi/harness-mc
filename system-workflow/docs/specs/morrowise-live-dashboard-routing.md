# MorroWise Live Dashboard Document Routing

> Task: `morrowise-live-dashboard-doc-routing` (`MC-LIVE-SYS-09`)
> Status: routing map
> Updated: 2026-06-21
> Scope: MorroWise live dashboard handoff paths for future Agents.

## Purpose

This document is the first file to read when continuing the MorroWise live dashboard.

It routes a future Agent to the right source without rebuilding the story from chat history. It does not replace the spec, mockup, read model, verifier, or MC task state. It explains when each one is authoritative.

Use this rule:

```text
tasks.json decides work state
specs decide contract
scripts generate read models
public/data shows current generated state
app/page.tsx displays read-only summaries
mockups explain intended information architecture
verifiers decide whether claims are checkable
```

## Update Boundaries

### Allowed Without Extra Approval

- Add or edit docs that clarify routing, source boundaries, or verifier entry points.
- Add local verifier coverage.
- Regenerate ignored `public/data/*.json` while testing.
- Produce a commit plan through `worktree-commit`.

### Requires Vincent Confirmation

- Commit, push, or deploy.
- Change task status.
- Write Heptabase, Notion, Obsidian Canvas, or other external mirrors.
- Change approval policy classes or runner write behavior.
- Treat a dashboard surface as fully live when verifier coverage is incomplete.

### Forbidden From Dashboard Itself

- Closing tasks.
- Mutating task state.
- Applying task events.
- Performing external sync.
- Committing, pushing, deploying, deleting files, or rewriting history.

## Verification Commands

Use the smallest verifier that matches the change.

| Change | Minimum check |
|---|---|
| Documentation-only routing update | `npm run test:tasks` when task metadata changes; otherwise markdown review and `rg` link/path check. |
| Read model contract/generator change | `npm run test:morrowise-live-dashboard` |
| Loop-chain or approval boundary change | `npm run test:morrowise-live-loop` |
| Homepage rendering or sidebar route change | route-map script or DOM/HTML check, plus `npm run build` |
| Task metadata change | `npm run test:tasks` |
| GitHub Pages deploy confidence | clean checkout `npm ci` + `npm run build`, then GitHub Actions run result |

For final completion claims, run `worktree-commit` before reporting verification results as closed task evidence.

## Handoff Checklist

Before marking any future MorroWise live-dashboard task complete:

1. The task has a clear `done_condition` in `milestones/harness-mc/tasks.json`.
2. The changed files match one coherent scope.
3. The relevant route map, contract, generator, UI, and verifier are aligned.
4. The surface still states or enforces read-only boundaries.
5. The relevant verifier passes.
6. `worktree-commit` was used before final completion.
7. The task has `status`, `completed_at`, `commits`, and `summary` aligned.
8. Dirty files from other sessions were not staged.
